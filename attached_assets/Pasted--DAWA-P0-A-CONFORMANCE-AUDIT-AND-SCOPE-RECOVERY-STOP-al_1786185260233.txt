--------------------------------------------------
AUTHORITATIVE P0-A PURPOSE
--------------------------------------------------

P0-A exists ONLY to prove:

FastAPI
→ Uplift Singapore API
→ one realtime Urdu assistant
→ one deliberate outbound Pakistani phone call
→ short two-way Urdu conversation
→ call lifecycle/status inspection.

Nothing else is required.

--------------------------------------------------
EXPECTED P0-A ARCHITECTURE
--------------------------------------------------

The authoritative runtime path must be:

UPLIFTAI_API_KEY
        ↓
one bootstrap-created realtime assistant
        ↓
UPLIFT_ASSISTANT_ID stored in environment
        ↓
POST /api/test-call
        ↓
POST Uplift /calls
        ↓
TEST_PHONE_NUMBER
        ↓
real Pakistani phone call

There must NOT be a requirement to create a different assistant for each
medication or each call.

- use UPLIFT_ASSISTANT_ID;
- query Uplift session status;
- not require SQLite or a webhook.

GET /health must remain independent of these future components.

If necessary, create a clearly isolated P0-A router or simplify the
existing routes, but make the smallest change possible.
